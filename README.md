# ContentLoom

Portfolio reference implementation of a 2025 project, built to show a product-copy generation pipeline at catalog scale. Thousands of SKUs and three locales go in; drafts are generated by Claude, scored automatically, and either published or routed to a human reviewer.

**Stack:** NestJS 10 API and workers, BullMQ on Redis, Anthropic TypeScript SDK (Claude Opus 5.5, with structured outputs for the judge), Next.js 14 review app.

## Pipeline
```
POST /batches (editor) → BullMQ "contentloom-generate" (jobId = itemId, 4 attempts, exponential backoff, 50/min limiter)
  worker: generate → score → route
    ├─ auto_approved ── publish (publisher role)
    └─ in_review ───── reviewer: approve (optionally edited) | reject | revise (note → regenerate, priority 1)
```
- **Scoring** (`api/src/llm.ts`) runs cheap checks first:
  - Deterministic checks for required facts (material, size), banned claims and length.
  - An **LLM judge** with a JSON-schema structured output (`output_config.format`): rationale, accuracy, usefulness, tone. Accuracy is weighted 2×.
- **Routing** (`api/src/domain.ts`) sends a draft to review whenever:
  - its category is regulated (baby, supplements, electrical);
  - any fact is missing or any banned claim appears;
  - the judge gave no verdict;
  - the score is under 0.85;
  - **or** it lands in a random 10% QA sample of drafts that would otherwise auto-approve.
  
  The QA sample is what measures **auto-approve precision** (`GET /metrics`), the number that justifies the threshold.
- **Revisions:** a reviewer's revision note goes back into the generation prompt, and the item re-queues at high priority.
- **Retries:** transient model errors retry through the queue's backoff. After the last attempt the item is marked `failed`, never silently dropped.
- **Lifecycle:** an explicit state machine. Illegal transitions (publishing an unreviewed draft, reviewing an item twice) return 409.
- **Roles** (from the SSO gateway): editors create batches, reviewers review, publishers publish.
- **Deployment:** the API and the workers are separate processes (`main.ts`, `worker.main.ts`), so workers can scale on queue depth.

## Review app (`review/`)
Shows the worst-scoring drafts first. Each one appears next to its product facts and the reasons it was flagged, with inline editing, a revision note, and approve / revise / reject.

## Test
```bash
cd api && npm install && npm test   # tsc + 7 e2e tests (Nest + supertest) with an in-memory queue and a fake Claude client
cd review && npm install && npm run build
```
The tests cover:
- Auto-approve and publish, plus the request shape (model, fallbacks, JSON-schema judge).
- Banned-claim, regulated-category and QA-sample routing.
- Edit-and-approve, and revision feedback reaching the writer prompt.
- Retry, then permanent failure.
- Role and lifecycle guards.
- QA-sample precision metrics.
